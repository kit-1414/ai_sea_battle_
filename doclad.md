## Приложение «Морской бой»

Приложение «Морской бой» представлено в трех версиях:

- версия 1 — максимально произвольная файловая структура, вся конфигурация OpenCode представлена в `opencode.json`;
- версия 2 — файловая структура максимально адаптирована для OpenCode, в `opencode.json` оставлено только необходимое;
- версия 3 — модифицированная версия 2, в которой с помощью ИИ была оптимизирована логика приложения: минимизированы вызовы агентов и т. п.

Наибольший интерес представляет первый проект, где вся конфигурация проекта находится в одном файле, поэтому все варианты сущностей видны сразу, а именно:

- `instructions` — файлы инструкций (правил и навыков), которые сразу загружаются в контекст при запуске OpenCode;
- `agents` — файлы агентов и субагентов. Агенты могут использоваться для запуска новой сессии OpenCode, принимать параметры или переключать контекст работы. Они доступны через `@`;
- `commands` — команды, доступные для вызова через `/`. Они служат для запуска агентов с параметрами, аналогично скриптам запуска приложений с аргументами. Примеры встроенных команд: `/build` и `/plan`.

### Контекст

В OpenCode (или в ИИ в целом) есть понятие контекста — набора знаний, инструкций и загруженных исходных файлов, в рамках которого ИИ выполняет работу.

Контекст существует в рамках сессии: он хранится в ней и меняется в процессе работы. Таким образом, сессия — это контейнер контекста.

Новая сессия создается каждый раз при запуске агента или субагента, в том числе при запуске OpenCode: пользователь запускает его с определенным агентом.

Агент или субагент при запуске наследует сессию родителя и обогащает свою сессию данными в процессе работы или выполнения команд пользователя.

При завершении работы агента его сессия либо уничтожается, либо сохраняется с определенным ID, по которому ее можно снова вызвать. Тогда агент начнет работу с уже сохраненным контекстом.

Агенты могут общаться между собой по принципу вызывающей и вызываемой функций: с помощью аргументов и результата, возвращаемого в конце работы. Содержимое дочерней сессии недоступно родительской.

При необходимости можно организовать обмен данными через внешние файлы, системы наподобие RabbitMQ и т. п.

### Инструкции

Файлы содержат знания, правила и описания: бизнес-логику проекта, правила написания кода и любые текстовые сведения, на основе которых ИИ должен анализировать или действовать (изменять файлы, выполнять расчеты или взаимодействовать с другими системами).

Они могут загружаться сразу при запуске OpenCode, по команде пользователя в текущем контексте либо агентами для получения необходимого им рабочего контекста.

### Агенты

Агент — это стартовая точка новой сессии OpenCode, которая загружает необходимые правила и инструкции и в рамках которой будет выполняться определенная работа.

Ключевой момент — создание новой отдельной сессии при запуске агента.

Агенты бывают двух видов: основные агенты и субагенты (`mode: primary | subagent`). Субагент может быть запущен другим агентом.

Пользователю доступны только публичные агенты и субагенты с атрибутом `hidden: false`.

В конфигурации видно, что для агента можно:

- задать стартовый промпт, указать файл с расширенным текстом промпта, перечень загружаемых инструкций и т. п.;
- настроить `permission` — перечень инструментов и атрибутов, определяющих, разрешен ли инструмент и, если разрешен, что именно ему доступно.

При настройке прав приоритет имеют последние правила. Например, можно сначала перечислить общие запреты, а затем добавить частичные разрешения или исключения.

### Инструменты (`tools`)

В OpenCode есть понятие инструментов — набора программных утилит, которые OpenCode запускает для выполнения типовых операций:

- редактор `edit` — можно разрешить или запретить чтение и запись определенных файлов, каталогов или файлов по маске;
- консоль `bash`;
- инструмент `Git`;
- инструмент `task`;
- другие инструменты.

### task (задача) 
  Task в OpenCode — это инструмент, с помощью которого основной агент поручает отдельную работу субагенту.

  Например, основной агент может:

   - запустить субагента explore для изучения проекта;
   - передать ему подробное задание;
   - получить итоговый результат;
   - продолжить ту же сессию по сохранённому task_id.
   
   Пример логики вызова:

   task(
     subagent_type="explore",
     description="Поиск API",
     prompt="Найди все REST-контроллеры и опиши их методы"
   )
   
   Особенности:
   - субагент работает в отдельной сессии и отдельном контексте;
   - основной агент получает результат, но не весь внутренний контекст субагента;
   - task_id позволяет повторно обратиться к той же сессии;
   - доступ регулируется через permission.task в конфигурации OpenCode;
   - task отличается от todowrite: task запускает субагента, а todowrite только ведёт список текущих задач.
   - В проекте «Морской бой» через task координатор запускает двух адмиралов и сохраняет их task_id, чтобы каждый адмирал помнил состояние своего поля до конца игры.

### Команды

Команда — это способ запустить агента с набором параметров.

- Приложение создавалось с помощью ИИ. Вручную был написан только первоначальный скрипт. Далее ИИ получал запросы: задать вопросы, исправить и улучшить приложение.
- Запуск версии 1 приложения: открываем OpenCode из каталога `ai_sea_battle_01`:
  - показываем доступных агентов;
  - показываем доступную команду, запускаем ее и комментируем процесс.
- Запуск версии 3 приложения: открываем OpenCode из каталога `ai_sea_battle_03`, запускаем команду и комментируем процесс, в том числе использование ID сессий.
